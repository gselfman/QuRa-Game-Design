# Техническое задание на реализацию

## 1. Архитектурное решение v0.1

Предлагаемый runtime — TypeScript + Babylon.js, WebGL2 как базовый проверяемый путь; WebGPU — дополнительная возможность после тестов, не условие запуска. Причины: браузерная среда QuRa, управление всей сценой через код, штатные камеры/render targets, glTF и скелетные анимации. Рекомендация не означает, что движок уже установлен или сравнительный performance-test пройден. Unity/Unreal не запрещены навсегда, но их смена требует пересмотра бюджета загрузки и автоматизации.

DOM/CSS HUD поверх canvas отделён от 3D-мира. Модули:

- `GameSession`: состояния попытки, патроны, ошибки, очки и переходы.
- `SimulationClock`: фиксированный шаг 1/120 с, pause/resume и seed.
- `ShotResolver`: траектория, swept collision, единственный terminal outcome.
- `AimController`: ввод, направление, sway, концентрация и recoil.
- `OpticsRenderer`: две камеры, render target, маска линзы, сетка/капли.
- `ChickenController`: perch/ability/drop/ground/penalty state machine.
- `InterferenceDirector`: расписание, telegraphs, чистые окна.
- `AnimationEvents`: связывает логические события с клипами и звуком.
- `AssetManager`: manifest, версии, загрузка, pools, освобождение памяти.
- `HostAdapter`: существующая QuRa-сессия, сохранение и будущие rewards.
- `Telemetry`: обезличенные события, замеры производительности, ошибки.

Симуляция не зависит от fps. Рендер интерполирует соседние состояния. При подвисании не проигрывать длинную серию непредсказуемых шагов: после ограниченного catch-up поставить техническую паузу без штрафа. Не использовать `Math.random()` в логике забега; хранить seed и индекс генератора. GPU-частицы декоративны и не влияют на попадание.

## 2. Контракт уровня

JSON содержит levelId, distanceM, targetDiameterM, environmentId, weaponLoadoutId, abilityIntensity, windStrength, scopeMagnification, flightTimeS. Дистанция — координата стойки в мире; диаметр — геометрический размер диска. Угловая читаемость проверяется отдельно. Пять rounds имеют явные IDs героинь. Не смешивать порядковый номер раунда с кодом персонажа.

JSON schema/version проверяются при загрузке. Неверный asset или ссылка останавливают запуск с понятной ошибкой, не подменяют Рябу случайной курочкой. Параметры текущей попытки заморожены; обновление balanceVersion вступает в силу со следующей попытки. Локальное сохранение содержит только прогресс тренировки; аккаунтный результат подтверждает host.

## 3. Данные и события

Session: id, mode, configVersion, seed, levelId, roundId, state, ammoRemaining, mistakes, score, streak, resolvedShotIds, targetsSolved. Shot: id, tick, origin, aimQuaternion, inputMode, result, impactTick, impactTargetId, normalizedRadius. Не сохранять секретные host-токены в replay.

События: `level_start`, `round_start`, `ads_enter`, `breath_hold_start/end`, `shot_fired`, `shot_resolved`, `ability_started`, `target_released`, `hen_landed`, `round_complete`, `level_complete/failed`, `pause`, `asset_error`, `webgl_context_lost`, `quality_changed`. Логирование не записывает движения пальца каждую отрисовку и не собирает реальные биометрические данные.

Для настоящих наград: server-owned session, ограниченные config/seed, идемпотентная сдача результата и защита от повторной выдачи, replay/checks по правилам QuRa. Клиентский счёт нельзя считать финансовым доказательством. Конкретные endpoint, цены входа, GE/XP и лимиты в этой работе не объявляются существующими и не меняются.

## 4. Производительность — целевые бюджеты, требующие измерений

Средний профиль: целевые стабильные 60 fps, frame budget 16.7 мс, две минуты живого прицеливания и полный уровень без накопления памяти. Базовый профиль: устойчивые 30 fps при упрощённых тенях/частицах, с тем же качеством логики и оптики. Устройства приёмки предварительно: iPhone 12 / Safari, iPhone 15 / Safari, Android уровня Snapdragon 778G / Chrome и актуальный средний Android; конкретные версии OS/browser записать в отчёте.

Стартовый загружаемый набор ≤20 MB compressed, последующие окружения подгружаются между уровнями. Общий контент кампании целевой ≤100 MB, GPU-память текстур ≤160 MB среднего профиля. Не обещать эти числа до готовых assets. Обычный кадр ориентир ≤150 draw calls, оптика суммарно ≤220; суммарно видимых треугольников с повторным проходом ≤350 тыс. на среднем профиле. Все параметры требуют профилирования реальной сборки.

Scope target 512/768/1024 px по профилю и размеру экрана; обновление синхронно с миром, не отдельные «дёрганые 15 fps». Сначала снижать scope resolution и сложность фонового прохода, а не его частоту. Ограничить DPR canvas до 1.5–2, HUD оставить чётким. Тени запекать для статики, одна мягкая динамическая область у целей; отражения преимущественно через environment map.

LOD выбирается по экранному размеру **каждой камеры**: в scope нельзя оставить дальнюю героиню в LOD2, если она крупная в линзе. Не выключать общий объект по culling основной камеры, если он виден второй. Текстуры и материалы прогреваются перед первым выстрелом; pools заранее. Капли, линза, стекло и перья контролируют overdraw. Не раздувать entire scene до кинематографического качества ради одного screenshot.

## 5. Устойчивость и среда

Ориентация/полноэкранный режим запрашиваются только допустимым пользовательским действием; отказ не блокирует игру. AudioContext стартует после tap. Потеря WebGL context — пауза, восстановление ресурсов, возврат без штрафа; не стартовать новую попытку молча. На уходе вкладки/звонке выключить loop/input и приглушить звук. После возврата не догонять пропущенные водяные атаки.

Статические assets versioned immutable; manifest/config — с контролем версии и актуальности. Использовать существующие CSP/CORS/auth host, не ослаблять всё приложение для одной игры. Сеть не нужна для каждого выстрела тренировки. При потере сети в аккаунтном режиме сохранить статус pending и не дублировать награду повторной отправкой.

## 6. Технические поставки

Исходники сцены/моделей, `.blend`, `.glb`, текстуры, authored clips, sound sources с лицензиями, manifests/checksums, lockfile зависимостей, воспроизводимая сборка, unit tests для правил, camera regression fixture, мобильный performance-report, краткий runbook. Для Blender-сборки проверять rigVersion и наличие всех клипов. Отсутствующая лицензия внешнего mesh/sound — незавершённый asset, даже если выглядит хорошо.

Первый spike должен доказать: корректную локальную оптику, попадание по движущемуся диску, живую каноническую Рябу и требуемый frame time на телефоне. Только после этого фиксируется окончательный renderer/character pipeline.
