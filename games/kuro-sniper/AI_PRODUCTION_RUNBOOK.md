# Инструкция: инструменты, которыми можно управлять через ИИ

## Что уже доступно и что требуется

Проверено 15.11.2026: Figma подключена; GitHub доступен через `gh`; Node.js и Python есть. **Blender 5.3.0 установлен для Apple Silicon** в `/Applications/Blender.app`, команда доступна как `/opt/homebrew/bin/blender`. macOS приняла notarized Developer ID приложения. Автоматический Python-запуск, сохранение `.blend`, Cycles CPU, EEVEE GPU через Metal и экспорт/обратная загрузка анимированного GLB проверены успешно. Рабочий профиль: EEVEE/Metal для быстрых превью, Cycles/CPU для проверенного офлайн-рендера. Cycles/GPU не заявляется проверенным: тесты остановлены на длительной компиляции. Подробности — в [отчёте установки](BLENDER_SETUP.md).

Поиск подключаемого Blender-плагина в текущем каталоге не дал результата. Управление уже работает через официальный Python API и командный режим; дополнительный MCP-плагин и платные 3D/animation-платформы для начала не нужны.

Предлагаемый набор:

| Инструмент | Задача | Как управляет агент |
|---|---|---|
| Figma | Образы, editable HUD, состояния, раскадровки | Подключённые инструменты и Plugin API |
| Встроенный генератор изображений | Концепты, текстуры, фоновые идеи | Промпты + обязательные референсы |
| Blender | Модели, rig, keyframes, материалы, рендер, GLB | Версионированные Python-скрипты `bpy`, headless CLI |
| Babylon.js + TypeScript | Живая сцена, оптика, анимации, эффекты | Исходный код, сборка и автоматические проверки |
| Playwright | Экранные сценарии, regression, desktop screenshots | Скрипты; реальные мобильные устройства дополнительно |
| Git/GitHub | Ветки, ревизии assets и заданий | CLI / подключённые инструменты |

Требуется отдельно подтвердить Blender-пилот и качество переноса персонажей. Наличие ИИ не гарантирует удачный rig с первой попытки. Гуманитарное описание движения превращается в формализованное задание: кости/контролы, длительность, ключевые позы, easing, ограничения, выходные файлы и проверка.

## Установка Blender на macOS

Один раз установить стабильную версию с [blender.org/download](https://www.blender.org/download/) либо, если Homebrew уже используется, командой `brew install --cask blender`. Homebrew ради одной команды не обязателен. Обычное место приложения — `/Applications/Blender.app`.

Проверка без настройки PATH:

```sh
/Applications/Blender.app/Contents/MacOS/Blender --version
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python-exit-code 1 --python games/kuro-sniper/tools/blender_probe.py -- --output /tmp/kuro-sniper-blender-probe
```

Запускать из корня репозитория. Скрипт создаёт диагностические `.blend`, `.glb`, PNG и JSON с версией; проверяет реальный рендер и изменение поворота после обратной загрузки анимации. Это **не модель курочки**. После успешного запуска версия Blender фиксируется в production manifest, чтобы повторная генерация не зависела от внезапного обновления. Диагностика не требует интернет-доступа, API-ключа или открытого порта.

Для независимости от порядка Intel/Apple Silicon Homebrew в PATH есть проектная команда:

```sh
bash games/kuro-sniper/tools/blender.sh --version
bash games/kuro-sniper/tools/blender.sh --background --factory-startup --python-exit-code 1 --python games/kuro-sniper/tools/blender_probe.py -- --output /tmp/kuro-sniper-blender-probe
```

Опция `--python-exit-code 1` обязательна в автоматических заданиях: ошибка Python должна завершать задачу ошибкой, а не выглядеть успешным запуском Blender. Сохранение настроек устройства Cycles не означает, что каждая новая сцена автоматически выбрала GPU: в скрипте рендера задавать `scene.render.engine='CYCLES'` и `scene.cycles.device='GPU'` явно.

Не устанавливать случайный community MCP с правом исполнять любой код только ради слова «нейросеть». Сначала CLI; если позже понадобится интерактивный bridge, отдельно выбрать поддерживаемое решение, проверить код и ограничить локальным доступом. Не открывать bridge в интернет.

## Производственный цикл без ручного моделирования как обязательного шага

1. Агент получает конкретный персонажный исходник и создаёт `asset job`: ID, source node, ревизия, формат, бюджет, клипы.
2. Выгружает исходные слои и референсы; сохраняет provenance и checksum. Не отправляет всю частную библиотеку во внешний сервис.
3. Создаёт Python-скрипт построения/адаптации модели. Для художественно сложной формы возможна image-to-3D заготовка после выбора сервиса; в v0.1 это опция, не скрытая зависимость.
4. Blender создаёт модель/rig, выставляет материалы, пишет keyframes по заданию, экспортирует GLB и контактный лист превью. Source `.blend` обязателен.
5. Агент проверяет JSON-отчёт: размеры, topology budget, имена костей, клипы, длительности, текстуры, отсутствие missing files. Затем смотрит отрендеренные кадры и при необходимости правит скрипт.
6. Подключает GLB в браузерную тестовую сцену, проверяет переходы, две камеры, коллизии и производительность.
7. Прикладывает в ветку исходники, job, prompt, проверки и превью. Художественные изменения утверждаются на конкретном результате; это не останавливает подготовку остальных независимых материалов.

Правки делаются параметрами и кодом: «меньше амплитуда хвоста», «лапа стоит на опоре», «взмах начинается на 220 мс». Не записывать в инструкцию «дальше вручную поправьте всё в Blender» как основной путь. Если автоматический путь не достигает сходства, это фиксируется как незакрытая задача, а не маскируется новой внешностью.

## Контракт задания для Blender-агента

Вход: `characterId`, reference images, `rigVersion`, список изменяемых controls, clip name, duration, loop, contact events, запрещённые изменения. Выход: `.blend`, `.glb`, `asset-report.json`, фронт/3⁄4/профиль preview и ключевые кадры. Без встроенного текста и baked HUD. Повторный запуск создаёт ту же структуру; новую ревизию сохранять отдельно, утверждённую не перезаписывать.

Для клипа `drop_flap`: тело сохраняет пропорции; root следует заданной дуге; лапы отпускают опору после защёлки; крылья раскрываются симметрично с характерным опережением; контакт земли отдельным событием. Случайный ragdoll не является заменой хорошей анимации.
