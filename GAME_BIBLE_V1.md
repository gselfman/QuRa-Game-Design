## 0. Зачем существует игра QuRa

Игра не является отдельным приложением, приклеенным к кошельку. Её продуктовая задача — сделать QuRa местом, куда пользователь хочет возвращаться чаще, знакомить его с возможностями сервиса и награждать за естественное полезное использование.

Основная петля:

**полезное действие в QuRa → XP / GE / прогресс задания → развитие выбранной курочки → награда → аксессуар / новая курочка / Курятник → новые игровые возможности → новый повод вернуться в QuRa.**

Правила:
1. Финансовая операция должна оставаться понятной и серьёзной. Игра не вмешивается в подтверждение платежа, курс, комиссию и статус денег.
2. Игровая награда может сопровождать успешное финансовое действие, но не заменяет финансовый результат.
3. XP и GE — разные системы. Получение одного не отменяет другого.
4. Нельзя создавать бесконечный выгодный цикл «потратил GE → сыграл → гарантированно получил больше GE».
5. Нельзя создавать характеристики, которые существуют только как цифры и ни на что не влияют.
6. Любая заявленная механика должна либо иметь конкретное применение, либо быть помечена Future и выключена из продукта.

# 1. Два связанных контура QuRa

## 1.1. Финансовый контур

Финансовый QuRa отвечает за баланс, пополнение, QR-оплату, доступные сервисы, будущие способы вывода/оплаты и начисление GE по экономическим правилам.

**GE принадлежит общему бонусному контуру QuRa, а не только игре.** По правилам финансового продукта GE может использоваться как бонус/скидка в разрешённых сценариях реального мира и одновременно расходоваться внутри Курятника.

Следствие: GE, заработанные в мини-играх, имеют реальную экономическую стоимость для QuRa как бонусное обязательство. Их эмиссия должна иметь бюджет, лимиты и антифрод.

## 1.2. Игровой контур

Игровой QuRa отвечает за:
- курочек;
- XP;
- уровни;
- Путь Курочки;
- ежедневные задания;
- аксессуары;
- Сундук;
- Курятник;
- мини-игры;
- игровые билеты;
- ежедневные события;
- Крутость;
- дары;
- Arena;
- Славу и лиги;
- 3D-воплощение и наследников.

Игровой контур может **получать сигналы** о завершённых финансовых действиях и начислять за них XP/прогресс заданий. Он не определяет финансовый статус операции.

# 2. Основные игровые величины

## 2.1. XP — опыт курочки

XP развивает **только выбранную главную курочку**.

XP:
- нельзя купить напрямую;
- нельзя вывести;
- нельзя передать;
- начисляется за задания, полезные действия QuRa, достижения и отдельные игровые активности;
- может иметь ограниченный процентный бонус от Дара/экипировки, но общий XP-boost должен иметь серверный cap.

Пользователь может менять главную курочку. XP нового действия получает та курочка, которая была главной в момент подтверждённого завершения действия.

## 2.2. GE — золотые яйца

GE — общий бонусный ресурс QuRa.

Источники игровой части:
- мини-игры;
- сундуки;
- level-up rewards;
- события;
- партнёрская программа;
- игровые достижения.

GE:
- не являются XP;
- не повышают уровень автоматически;
- расходуются на аксессуары, улучшения Курятника, дополнительные игровые попытки, сундуки и другие разрешённые игровые функции;
- могут иметь неигровое применение по правилам финансового продукта;
- не переводятся напрямую с баланса пользователя на баланс другого пользователя.

Все источники GE обязаны хранить `source_type` для аналитики и контроля эмиссии.

## 2.3. Игровые билеты

Билеты ограничивают **бесплатные наградные попытки в мини-играх**, а не сам доступ к миру QuRa.

Правило v1:
- +2 билета в сутки;
- максимальный запас — 8;
- одна наградная попытка мини-игры = 1 билет;
- после окончания билетов пользователь может играть за GE, если конкретная игра это поддерживает;
- стоимость дополнительной попытки задаётся по игре на сервере;
- билет не используется в Arena.

Для платной GE-попытки ожидаемая средняя GE-награда на длинной дистанции должна быть ниже стоимости входа, иначе возникает бесконечный фарм. Бесплатные билеты рассматриваются как retention/marketing budget.

## 2.4. Крутость

Крутость — постоянная коллекционно-прогрессионная оценка курочки и Курятника. Она нужна для:
- рейтинга;
- требований к улучшению Курятника;
- коллекционных целей;
- визуального статуса;
- части достижений.

Крутость **не меняется от ежедневной погоды, временного бафа, Боевого духа или результата одного боя**.

Предварительная формула курочки:

`ChickenCoolness = LevelScore + GearCoolness + SetBonus + LegacyBonus + AchievementBonus`

Формула должна быть таблицей, а не зашита в UI.

## 2.5. Дар

Дар — постоянная уникальная пассивная способность курочки вне Arena. Дар должен влиять на реальную систему: магазин, XP, события, яйценоскость, синергию и т.п.

Два одинаковых Дара одного семейства **не складываются бесконечно**: по умолчанию применяется самый сильный эффект семейства. Разные семейства могут сочетаться.

# 3. Жизненный цикл курочки — L1–L20

| Уровень | Форма | Ключевое открытие |
|---|---|---|
| L1 | Яйцо | начало развития |
| L2 | Яйцо с признаками развития / трещиной | первые задания |
| L3 | Цыплёнок | выбор первой базовой курочки / раскрытие типа нового яйца |
| L4 | Взрослая курочка | магазин, гардероб, обычные аксессуары, Arena 1×1 |
| L5–L14 | Развитие | новые предметы, награды, задания, более сильный Дар |
| L15 | Зрелая курочка | право на 3D-воплощение |
| L16–L19 | Prestige-развитие | high-tier контент |
| L20 | Максимальный уровень текущего поколения | endgame-награда / статус |

## 3.1. Почему аксессуары начинаются с L4

На L1–L2 курочки ещё нет. На L3 существует цыплёнок. Полноценная экипировка появляется только вместе со взрослой курочкой на L4.

Поэтому:
- обычных аксессуаров L1, L2, L3 **не существует**;
- стандартные аксессуары имеют `min_level >= 4`;
- курочка может носить предмет своего уровня и ниже;
- предмет выше уровня курочки надеть нельзя;
- специальные предметы могут иметь `ignore_level_gate = true`, но всё равно требуют взрослую форму L4+.

## 3.2. Первая и последующие курочки

Первая курочка:
- L1 — базовое яйцо;
- L3 — пользователь выбирает одну из семи базовых основательниц;
- L4 — появляется взрослая версия выбранной курочки.

Дополнительные курочки всегда поступают в виде яйца L1.

Тип дополнительного яйца может быть:
- известным заранее (куплена конкретная курочка);
- скрытым до раскрытия (случайная награда);
- специальным/легендарным.

Каждая курочка развивается отдельно.

# 4. Главная курочка

Пользователь выбирает одну курочку **главной**.

Главная:
- показывается на Главной QuRa;
- получает XP от общих account-level действий и заданий;
- является фокусом текущего развития;
- может быть изменена пользователем.

Остальные жители Курятника сохраняют свои уровни, XP, экипировку и Дары.

Смена главной не должна требовать GE. XP закрепляется за той курочкой, которая была главной **в момент фактического завершения действия/задания**, а не в момент позднего нажатия «Забрать». Это исключает перенос уже заработанного XP между курочками задним числом.

## 4.1. Scope заданий и одноразовых действий

Задания принадлежат либо аккаунту, либо конкретной курочке. Это обязательное различие в data model.

### ACCOUNT_ONCE
Одноразовые задания знакомства с QuRa:
- заполнить профиль;
- настроить уведомления;
- установить PWA на главный экран;
- подключить Telegram;
- впервые пополнить;
- впервые оплатить по QR;
- впервые использовать доступный сервис;
- впервые пригласить друга и т.п.

Такое задание выполняется **ровно один раз на аккаунт**. После выполнения оно никогда не появляется снова, даже если пользователь сменил главную курочку или получил новую. XP получает главная курочка на момент выполнения.

### CHICKEN_ONCE
Одноразовые задания, смысл которых относится именно к конкретной курочке и потому может повторяться у каждой новой курочки:
- впервые экипировать эту курочку;
- впервые собрать на ней родной set threshold;
- впервые выиграть ею бой;
- впервые активировать её Дар в событии;
- достичь конкретного milestone уровня.

CHICKEN_ONCE не должен повторять обучение интерфейсу.

### DAILY_ACCOUNT / WEEKLY_ACCOUNT
Единый набор ежедневных/недельных заданий аккаунта. Они не дублируются по числу курочек. XP получает главная курочка в момент завершения конкретного задания.

### ACHIEVEMENT_ACCOUNT
Долгосрочные достижения аккаунта, выполняемые один раз: коллекции, число операций, победы, уровень Курятника и т.п. Награды принадлежат аккаунту; если в награде есть XP, он закрепляется за главной курочкой в момент выполнения достижения.

## 4.2. Как развивать вторую и последующие курочки

Новая курочка **не получает повторный onboarding QuRa**. Она развивается за счёт:
- новых DAILY/WEEKLY заданий аккаунта, пока выбрана главной;
- текущих финансовых/продуктовых действий, дающих XP;
- мини-игр и Arena, если они дают XP по правилам;
- CHICKEN_ONCE задач роста;
- событий и специальных quest-линий.

Таким образом аккаунт прогрессирует глобально, а пользователь сам решает, в какую курочку направлять новый XP, выбирая её главной.

# 5. Семь основательниц

Семь стартовых курочек — **первое поколение мира QuRa, а не предел коллекции**. В будущем добавляются редкие, сезонные, партнёрские и легендарные персонажи.

Текущая структура:

### Ряба
**Дар: Золотая несушка.** Улучшает пассивную яйценоскость Курятника. Сила Дара растёт с уровнем.

### Деймимурочка / Гламурочка
**Дар: Шопинг с характером.** Даёт скидку на определённые игровые покупки/апгрейды. Конкретные категории и cap задаются экономикой.

### Курочка-Дурочка
Весёлая, цветастая, авантюрная.
**Дар: Везучая дурочка.** Даёт шанс перевернуть негативное событие Курятника в специальный положительный исход.

### Курочка-Боевик
**Дар: Охрана.** Может полностью заблокировать часть событий категории «угроза/нападение». Вероятность/порог растёт с уровнем.

### Курочка-Монах
Привязана к месту, «заливает благодатью» Курятник.
**Дар: Благодать.** Усиливает именно бонусы синергии Курятника, а не базовую Крутость напрямую. Чем больше в Курятнике комплектов и взаимодействий, тем ценнее Монах.

Принцип формулы:
`FinalSynergyBonus = RawSynergyBonus × (1 + GraceModifier)`

### Курочка-Профессор (Недурочка)
**Дар: Научный подход.** Увеличивает XP за подходящие задания/действия в пределах общего XP boost cap.

### Седьмая основательница
Имя/визуал берутся из утверждённого набора персонажей. **Дар пока не фиксируем**, чтобы не придумывать способность без отдельного продуктового решения.

> Классы («торговец», «монах», «защитник» и т.д.) **не показываются пользователю в v1**. Это будущая систематика, когда персонажей станет существенно больше семи.

# 6. Легендарные и будущие курочки

В будущем мир может включать:
- Rare;
- Epic;
- Legendary;
- event/seasonal;
- partner;
- наследников.

Легендарная курочка не должна быть просто «та же курица, но +50% ко всему». Хороший Legendary меняет стратегию:
- особый Дар;
- необычные trade-offs;
- уникальное взаимодействие с событием;
- редкий Arena Special.

Это создаёт коллекционность без линейного pay-to-win.

# 7. Курятник и вместимость

Каждая принадлежащая пользователю сущность «курочка» занимает одно место независимо от стадии: яйцо, цыплёнок или взрослая.

Лестница v1:

| Tier | Название | Вместимость | Получение |
|---|---|---:|---|
| I | Гнёздышко | 2 | старт |
| II | Курятник | 4 | первый апгрейд дарится за progression |
| III | Птичий двор | 6 | покупка/условия |
| IV | Усадьба | 10 | GE + требования |
| V | Золотой двор | 16 | GE + Крутость/коллекция |
| VI | Дворец Рябы | 24 | endgame |

Первое расширение 2 → 4 пользователь получает бесплатно в подходящий момент Путя. Следующие являются значимым GE sink.

## 7.1. Переполнение

Если Курятник заполнен:
- купить новую курочку нельзя;
- призовая курочка/яйцо не исчезает мгновенно;
- пользователь получает экран выбора:
  1. расширить Курятник;
  2. освободить место;
  3. отказаться от награды;
  4. «решить позже».

Наградная курочка помещается в временное состояние **«В гостях»** на ограниченный срок (начальная гипотеза — 24 часа). До истечения срока пользователь должен принять решение.

Выселение существующей курочки требует двойного подтверждения. Модель дальнейшей судьбы выселенной курочки (удаление, приют, рынок) **не входит в v1** и должна быть определена до включения кнопки.

# 8. Крутость Курятника

Крутость Курятника нужна для рейтинга и progression, но не является боевой силой.

Предварительно:

`CoopCoolness = Σ ResidentCoolness + BuildingBonus + CollectionBonus + FinalSynergyBonus`

Где:
- `ResidentCoolness` — Крутость жителей;
- `BuildingBonus` — бонус уровня Курятника;
- `CollectionBonus` — завершённые коллекции/достижения;
- `FinalSynergyBonus` — сетовые и прочие синергии, усиленные Монахом.

Полная коллекция семи основательниц должна давать отдельный коллекционный бонус.

**Daily Events не меняют Крутость.**

# 9. Аксессуары

## 9.1. Категории

Базовый каталог:
- головные уборы;
- очки;
- серьги;
- шея: бусы/цепочки;
- платки/шарфы;
- одежда/броня;
- сумочки/предмет крыла;
- обувь;
- окрас/перья (skin);
- хвостовые украшения;
- значки/медали;
- ауры/визуальные эффекты.

Не все категории обязаны быть одновременно активными слотами. Точный набор слотов фиксируется в Gear Spec после проверки визуальной читаемости.

## 9.2. Уровни и редкость

Обычный ассортимент начинается с L4 и продолжается до L20.

Рекомендуемые rarity:
- Common;
- Rare;
- Epic;
- Legendary;
- Artifact.

**Artifact** — специальный верхний класс вместо внутреннего рабочего названия AAAA.

Сам факт Rare/Legendary не обязан снимать level gate. Для предметов, которые можно носить на любой взрослой курочке, используется отдельный признак `ignore_level_gate`. Artifact по умолчанию может его иметь.

## 9.3. Родные предметы

У каждой базовой курочки есть собственная визуальная линия аксессуаров.

Любая взрослая курочка может носить чужой предмет, если соблюдён уровень.

Если предмет надет на «родную» курочку:
- даётся native synergy;
- родные комплекты дают дополнительные set bonuses.

Порог комплекта не фиксируем глобально. Конкретный set может иметь бонусы 2/4/6 либо другую структуру.

## 9.4. Два слоя характеристик предмета

Каждый предмет имеет:

### Сегодня
- Крутость;
- native/set synergy;
- при необходимости реальный metagame effect.

### Arena · скоро
Затемнённый, но читаемый блок будущих характеристик:
- Жизнь;
- Атака;
- Защита;
- Скорость;
- возможный modifier Особого приёма.

Это честно показывает будущую ценность покупки до запуска Arena.

---

# 10. Боевые характеристики Arena

Не копируем шесть Pokémon-статов без механической необходимости.

Для QuRa v1 Arena:

- **Жизнь (HP)** — сколько урона выдерживает курочка;
- **Атака** — базовый атакующий потенциал;
- **Защита** — уменьшает входящий обычный урон;
- **Скорость** — влияет на порядок/инициативу;
- **Особый приём** — уникальная способность персонажа, а не число.

Special Attack / Special Defense **не вводятся**, пока в дизайне боя нет отдельной системы физических и специальных атак. Если такая система появится позже, это отдельная миграция правил.

# 11. Особый приём

Особый приём существует только в Arena и уникален для персонажа.

Примеры направления:
- Дурочка — рискованный «Авось!» с шансом очень сильного эффекта и шансом провала;
- Боевик — контратака/защитная реакция;
- Профессор — игнор части защиты/расчёт следующего хода;
- Монах — командная защита/восстановление;
- Ряба — щит/защитное яйцо.

Точные значения не входят в Game Bible v1; они будут в Arena Balance Spec.

# 12. Сундук сокровищ — inventory

Сундук общий для всего Курятника.

В v1 упрощаем вместимость:
- один неэкипированный аксессуар = одно место;
- экипированный предмет находится на курочке и место Сундука не занимает;
- дубликаты можно хранить столько, сколько позволяет вместимость;
- никакого отдельного ресурса «Пух и перья» в v1.

Расширение Сундука идёт trade-in:
**старый Сундук + GE → новый более вместительный Сундук.**

Если награда выпала при полном Сундуке, она помещается во временную посылку/overflow и не должна исчезать мгновенно. Пользователь выбирает: экипировать, продать дубль, расширить Сундук или освободить место.

## 12.1. Дубликаты

Дубликат можно:
- оставить;
- экипировать на другую курочку;
- обменять на GE.

Начальная цена выкупа:
**25% от текущей магазинной цены данного item**.

Это серверная настройка `duplicate_sellback_pct`, а не константа UI.

Одинаковый item имеет одинаковую sellback price независимо от того, был он куплен или выпал как награда.

# 13. Визуальный контракт курочки

Для каждой базовой курочки требуется три runtime-позы и один promo-образ.

## A. CARD
Стоит красиво 3/4. Используется в:
- карточке;
- магазине;
- гардеробе;
- примерке;
- Arena.

## B. PERCH
Сидит на жердочке. Используется в Курятнике.

## C. NEST
Курочка **сразу отрисована в своём гнезде**. Используется на Главной. Nest не собирается позднее из двух независимых картинок.

## D. PROMO MAX
Полностью готовая курочка в идеальном родном комплекте — aspiration/reference для промоматериалов. Это не runtime skeleton.

Все семь базовых курочек в каждой runtime-позе должны иметь стандартизированную геометрию привязки аксессуаров: голова, глаза, шея, корпус, крылья, хвост, лапы.

Один логический аксессуар может иметь до трёх pose-variants. Если слот в позе физически не виден (например обувь в NEST), отдельный sprite не требуется, но предмет остаётся экипирован и его эффекты действуют.

# 14. Путь QuRa и личный путь курочки

Старое понятие «Путь Курочки» разделяется на два слоя, чтобы новая курочка не заставляла пользователя повторять знакомство с приложением.

## 14.1. Путь QuRa — account-level, одноразовый

Это длинная последовательность `ACCOUNT_ONCE` заданий, знакомящая пользователя с реальными возможностями QuRa и игрового мира. Она существует **один раз на аккаунт** и не сбрасывается при смене главной курочки.

Примерные главы:
- Знакомство — профиль, безопасность, PWA, Telegram;
- Первые деньги — пополнение, первая оплата, история;
- Первый Курятник — выбор курочки, мини-игра, Сундук;
- Хозяйство — аксессуар, комплект, расширение Курятника;
- Компания — реферал, друг, гостевой визит;
- Дальнейшие сервисы — только реально включённые feature-gated возможности QuRa.

XP за выполненное задание получает главная курочка на момент завершения.

## 14.2. Личный путь курочки — chicken-level

У каждой курочки существует собственная progression-линия L1–20, но она **не повторяет onboarding приложения**.

Структура жизненного пути:
- L1–3: Вылупление;
- L4–6: Новый дом;
- L7–10: Характер;
- L11–14: Мастерство;
- L15: Наследие;
- L16–20: Легенда.

Её задачи относятся к самой курочке: экипировка, родной комплект, участие в Arena, срабатывание Дара, уровневые milestones и специальные character quests.

Примеры заданий, если функция реально доступна:
- заполнить профиль;
- настроить уведомления;
- добавить PWA на главный экран;
- подключить Telegram;
- пополнить;
- совершить QR-оплату;
- оплатить по ссылке;
- загрузить QR из медиатеки;
- использовать доступный сервис (телефон, интернет, ЖКХ, штраф, заправка и т.п.);
- пригласить друга;
- сыграть мини-игру;
- потратить игровые билеты;
- получить сундук;
- купить/надеть аксессуар;
- собрать комплект;
- выбрать вторую/третью курочку;
- улучшить Курятник.

**Задание нельзя показывать, если соответствующая функция QuRa не включена.** У задания есть feature gate.

# 15. Ежедневные задания

Отдельно от Путя пользователь получает короткий daily-набор.

Базовая гипотеза:
- 3 задания в день;
- задания тасуются из pool;
- полный набор даёт Daily Chest / бонус;
- финансовое действие не обязано присутствовать ежедневно;
- повторяемые операции имеют diminishing XP или дневные ограничения, чтобы нельзя было фармить XP микроплатежами.

Пример:
- зайти в Курятник;
- сыграть одну игру;
- посмотреть «Новости Курятника»;
- примерить предмет;
- выполнить одну реальную оплату;
- навестить друга;
- выиграть тренировочный бой.

# 16. XP и уровни

Финальная XP-кривая оформляется отдельной таблицей после моделирования реальной частоты действий.

Требования:
- 20 уровней;
- L3 и L4 достигаются достаточно быстро, чтобы пользователь быстро увидел персонажа;
- первые три взрослых курочки должны появляться существенно быстрее, чем последующие;
- L15 является заметной долгосрочной целью;
- L20 не должен достигаться за несколько недель обычного использования;
- XP нельзя бесконечно фармить повтором одной дешёвой операции.

XP источники и награды должны быть серверными настройками.

# 17. Level-up reward

Каждый новый уровень — reward moment.

Пользователь получает сундук/награду, открываемую вручную.

Потенциальное содержимое:
- GE;
- обычный аксессуар;
- Rare/Epic/Legendary/Artifact item;
- игровые билеты;
- специальное яйцо курочки;
- временный игровой бонус.

Результат всегда определяется на сервере и логируется.

# 18. Reward chests и drop economy

Базовая модель rarity должна быть прозрачной и серверно управляемой.

Стартовая **гипотеза для моделирования**, не финальный баланс:
- Common ~60%;
- Rare ~28%;
- Epic ~9%;
- Legendary ~2.5%;
- Artifact ~0.5%.

Для платного сундука вероятности показываются пользователю до покупки.

Reward pool зависит от progression: ранний игрок в основном получает доступные ему предметы; небольшой preview следующего уровня допустим, но нельзя выдавать поток L20-вещей игроку L4.

Нужен anti-bad-luck / pity counter для дорогих сундуков. Параметры определяются в Economy Spec.

# 19. Ежедневные события — «Новости Курятника»

Событие дня **глобально одинаковое для всех игроков**. Это создаёт общий живой мир и честную базовую среду.

Результат события индивидуален, потому что учитываются жители, Дары и временные эффекты конкретного Курятника.

Не делаем 365 полностью уникальных событий. Цель контента:
**60–80 базовых событий** + 2–3 текстовых варианта + индивидуальные реакции. Это создаёт сотни воспринимаемых комбинаций без неподдерживаемого объёма контента.

Категории:
- погода;
- угрозы;
- еда/урожай;
- внешний мир;
- внутренние события;
- редкие/магические.

События имеют rarity и cooldown от повторения.

## 19.1. Lucky Flip

Каждое негативное событие обязано иметь заранее подготовленную положительную альтернативу для механики удачи.

Пример:
**Ночью лил сильный дождь. Курятник подтопило → яйценоскость −10%.**

Если сработала Дурочка:
**После дождя вылезли черви. Курочки устроили пир → яйценоскость +5%.**

Это не просто «negative = 0», а отдельный сюжетный позитивный исход.

## 19.2. Порядок обработки

Для отрицательного события:
1. выбрать глобальное событие;
2. проверить Lucky Flip;
3. если flip не сработал — проверить hard counter (например Боевик);
4. применить mitigation (например Благодать/другие эффекты);
5. применить итоговый временный modifier.

Одинаковые способности одного семейства не стакаются; используется сильнейшая.

## 19.3. На что события могут влиять

Разрешённые временные цели:
- пассивная яйценоскость;
- цена/скидка отдельных игровых категорий;
- XP bonus;
- drop chance;
- Arena temporary stats;
- игровые билеты/награды;
- будущие временные системы.

**События не меняют Крутость.**

- «Волк ловит яйца»;
- «Выживание на Птичьем дворе».

- большие награды должны быть редкими и логироваться;

Другие бонусные предметы/эффекты добавляются отдельным Game Reward Catalog.

# 21. Arena: зачем она нужна

Arena — не «игра ради игры». Она создаёт:
- применение будущих боевых характеристик аксессуаров;
- причину собирать несколько курочек;
- мету команд;
- GE sinks через подготовку/бафы;
- сезонную Славу;
- лиги;
- награды;
- социальные вызовы;
- Зал славы.

Arena не влияет напрямую на финансовый баланс.

# 22. Arena unlock path

Arena не ждёт трёх курочек.

### Duel — 1×1
Открывается, когда первая курочка стала взрослой (L4). Это обучение боевой системе.

### Pair — 2×2
Открывается при двух взрослых курочках.

### League Team — 3×3
Открывается при трёх взрослых курочках. Это основной ranked-режим сезонов.

Дизайн-цель progression: игрок должен относительно быстро получить первых трёх курочек; дальнейшее расширение коллекции значительно сложнее.

1×1 и 2×2 могут давать rewards/прогресс Arena Path, но **сезонный рейтинг и Зал славы строятся на 3×3**. Это сохраняет честность рейтинга и одновременно позволяет играть с первой курочкой.

# 23. Arena: действия в бою

MVP-ход:
- Атаковать;
- Защищаться;
- Особый приём.

Бой пошаговый.

Скорость влияет на инициативу/порядок. Остальные формулы определяются Arena Balance Spec.

Не вводим Special Attack/Special Defense, пока не появится отдельная система типов атак.

---

# 24. Battle Power

Battle Power используется только для matchmaking.

Он рассчитывается из **постоянной боевой силы выбранного состава**:
- базовые Arena stats курочек;
- уровень;
- постоянные stats экипировки;
- постоянные set bonuses;
- допустимые наследственные modifiers.

**Battle Power намеренно НЕ учитывает:**
- Боевой дух;
- активный временный баф;
- Daily Event modifier;
- временные боевые статусы.

Поэтому две равные по BP команды могут иметь разный фактический потенциал в конкретный день.

---

# 25. Боевой дух

Боевой дух — временное состояние Arena, не постоянный stat курочки и не Крутость.

Рабочий диапазон: примерно **−15% … +15%** (финальная таблица позже).

Он:
- растёт на серии побед;
- падает после поражений;
- модифицирует итоговую боевую эффективность;
- не входит в matchmaking BP;
- постепенно возвращается к 0 со временем, чтобы не возникал необратимый death spiral;
- не покупается напрямую за GE в v1.

После начала боя противник видит, что у команды повышенный/пониженный дух, чтобы усиление не ощущалось скрытым жульничеством.

---

# 26. Arena buffs — GE sink

Игрок может купить за GE временную подготовку команды.

Правила v1:
- одновременно активен **один** Arena buff;
- длительность, например 12/24 часа;
- buff не входит в Battle Power;
- после начала боя активный buff становится виден сопернику;
- сила ограничена и не должна гарантировать победу.

Примеры:
- Боевой завтрак — HP bonus;
- Оберег Курятника — Defense bonus;
- Крепкий кофе — Speed bonus;
- Благословение — modifier Special.

Монах может усиливать положительные синергии/бафы только в рамках жёсткого cap, чтобы не появлялся неконтролируемый stacking.

Дополнительные GE sinks Arena:
- косметические рамки;
- banners;
- победные эмоции/анимации;
- визуал команды.

**Покупка дополнительных ranked-побед/Славы за GE запрещена.**

---

# 27. Arena participation и offline defense

Игрок **не участвует в сезонной Arena автоматически**.

Чтобы войти в сезон:
1. открыть Arena;
2. подтвердить участие;
3. собрать защитную команду;
4. выбрать защитную тактику.

До этого его Курятник не появляется в ranked matchmaking.

Асинхронная защита использует сохранённую defensive strategy. Защитник не обязан быть онлайн.

Примеры AI-тактик:
- Агрессивная;
- Осторожная;
- Хитрая / бережёт Special.

Нападающий играет свой бой вручную.

## 27.1. Слава за offline defense

Чтобы пользователь не стал №1, неделю не заходя:
- основная Слава зарабатывается активными ranked-атаками;
- успешная защита даёт небольшой bonus Glory;
- бонус защиты имеет дневной cap;
- поражение offline defense не должно резко обрушивать рейтинг.

---

# 28. Matchmaking и защита от фарма

## 28.1. Ranked matchmaking

Славу и изменение Боевого духа даёт **только ranked matchmaking**, где игрок не выбирает конкретного соперника.

Приоритет:
1. тот же ranked format;
2. близкая лига/рейтинг;
3. Battle Power примерно ±10%;
4. расширение окна при отсутствии соперника;
5. ranked bot соответствующей силы — только если это отдельно разрешено правилами сезона, с уменьшенной наградой.

Игрок всегда видит, реальный соперник перед ним или бот.

После подбора сервер фиксирует snapshot состава, экипировки и Battle Power на этот бой. Нельзя найти слабого противника, а затем заменить экипировку/команду до расчёта результата.

## 28.2. Дружеский бой

Кнопка «Вызвать друга» запускает **Friendly Battle**, а не ranked-матч.

Friendly Battle:
- не даёт Славу;
- не повышает и не понижает Боевой дух;
- не меняет лигу;
- не даёт обычные ranked season rewards;
- может использоваться без ограничения для практики и развлечения.

Чтобы дружеские бои всё же стимулировали social use, отдельное DAILY/WEEKLY задание может один раз выдать XP/небольшую награду за «Сыграть с другом». Награда идёт через quest system, а не за каждую победу. Поэтому сильный игрок не может бесконечно фармить слабого друга.

## 28.3. Тренировка с ботом

Training Battle:
- не даёт Славу;
- не меняет Боевой дух;
- предназначен для изучения тактики;
- может учитываться в специальных заданиях с дневным cap.

## 28.4. Anti-farm ranked

Даже в случайном matchmaking сервер хранит недавних соперников:
- старается не соединять одну пару повторно в коротком окне;
- повторные встречи в пределах anti-farm window получают понижающий reward coefficient либо нулевой Glory после лимита;
- Glory gain/loss дополнительно зависит от разницы рейтинга: победа над заведомо более слабым случайным соперником даёт меньше Славы, победа над более сильным — больше.

Friend/referral relation не даёт отдельного ranked-преимущества и не позволяет выбрать друга как рейтингового соперника.

---

# 29. Слава, лиги и Зал славы

**Крутость** = развитие/коллекция.  
**Слава** = сезонный Arena performance.

Примерная лестница:
- Дворовая лига;
- Фермерская;
- Золотая;
- Алмазная;
- Королевская.

Точные thresholds — отдельный balance table.

TOP-3 текущего сезона получают видимые медали 🥇🥈🥉.

После окончания сезона:
- сезон фиксируется;
- чемпионы навсегда попадают в **Зал славы**;
- сохраняется snapshot состава победителя на конец сезона;
- исторические медали остаются в профиле.

Season rewards: GE, сундуки, аксессуары, cosmetic status, билеты; не реальные деньги.

---

# 30. Друзья и социальный слой

Географическая/бесконечная карта Курятников **не входит в план**.

Пользователь видит друзей из партнёрской программы:
- имя;
- Курятник;
- Крутость;
- доступную публичную карточку;
- «Зайти в гости»;
- «Вызвать на бой», если Arena доступна.

В Arena:
- **Вызвать друга** → Friendly Battle, без Славы и изменения Боевого духа;
- **Найти соперника** → Ranked matchmaking, источник Славы;
- **Тренировка** → бот, без Славы и изменения Боевого духа.

Просмотр чужого Курятника по произвольному email не включается в v1 из-за privacy/abuse. Доступ строится через существующие социальные связи или явный публичный идентификатор в будущем.

## 30.1. Friendly Battle: online и приглашения

Дружеские бои имеют два пользовательских сценария.

### Online Friendly
Если оба игрока онлайн и друг принимает вызов, запускается синхронный пошаговый PvP.

На каждом ходу оба игрока **одновременно и скрытно** выбирают действие:
- Атаковать;
- Защищаться;
- Особый приём, если доступен.

После выбора обоих игроков действия раскрываются одновременно и Battle Engine рассчитывает результат хода.

Это создаёт отдельный слой психологии: игрок не знает заранее выбор соперника и пытается предугадать его тактику.

### Friend Challenge
Если друг офлайн, пользователь может оставить ему приглашение на бой.

При следующем входе друг получает уведомление о вызове и может:
- принять;
- отклонить;
- отложить.

Принятие приглашения **не запускает бой автоматически против AI-копии друга**. Основной social-сценарий — дождаться, когда оба игрока окажутся онлайн, и начать живой Friendly Battle.

Асинхронный Friendly против defensive strategy может быть добавлен позже как отдельный режим, но не является обязательным для первого релиза online-friendly.

## 30.2. Таймер хода и reconnect

Для online Friendly нужен ограниченный таймер решения. Начальная гипотеза — около 20 секунд на ход.

Если игрок не выбрал действие:
- Battle Engine применяет заранее определённое безопасное действие по умолчанию (базовая гипотеза — «Защищаться»);
- несколько последовательных пропусков могут приводить к техническому поражению.

При кратковременном разрыве соединения клиент получает окно reconnect. Точные значения таймеров определяются в Arena Spec.

## 30.3. Один Battle Engine для всех режимов

Боевая математика не должна дублироваться.

Один серверный Battle Engine принимает состояние боя и решения сторон. Отличается только источник решения:

- **Online Friendly** → решение второго живого игрока;
- **Ranked asynchronous defense** → defensive AI strategy;
- **Training** → bot AI;
- **будущий online Ranked** → второй живой игрок, если такой режим когда-либо будет утверждён.

Это обязательное архитектурное правило: добавление online PvP не должно создавать вторую несовместимую систему расчёта боя.

## 30.4. Награды Friendly

Friendly Battle:
- не даёт Славу;
- не меняет Боевой дух;
- не влияет на лигу;
- не даёт стандартные ranked rewards.

При этом Daily/Weekly Quest может один раз засчитать «Сыграть с другом» и выдать ограниченную XP/социальную награду. Победы над одним другом нельзя использовать для бесконечного фарма.

# 31. Партнёрская программа

Актуальная игровая модель:
**20% / 10% / 4%** GE по уровням партнёрской программы за учитываемые реальные действия приглашённых.

Регистрация без действия не даёт награду.

Партнёрская программа связана с:
- GE;
- заданиями;
- social/friends;
- гостевым просмотром;
- friend challenge Arena.

Она не должна автоматически влиять на Крутость.

# 32. Пассивная яйценоскость

Яйценоскость — **выход системы**, а не ещё один обязательный стат карточки.

Она рассчитывается из:
- базового производства взрослых курочек;
- уровня/прогрессии;
- Дара Рябы;
- Daily Event;
- разрешённых set/effect modifiers;
- экономического cap Курятника.

Формула и лимиты будут в Economy Spec.

Причина cap: GE может использоваться за пределами игры, поэтому Курятник на 24 места не должен создавать неконтролируемое бонусное обязательство.

---

# 33. Наследники и 3D

L15 даёт право **воплотить курочку в физическую 3D-фигурку**.

При воплощении:
- исходная курочка покидает цифровой Курятник;
- освобождается место;
- создаётся возможность наследника;
- фигурка получает уникальный паспорт/идентификатор и одноразовый скрытый QR-код наследования.

Наследник:
- появляется яйцом L1;
- наследует визуальные/родословные признаки;
- получает `LegacyBonus`;
- развивается быстрее предка по контролируемому коэффициенту;
- не получает автоматически уровень L15.

Ускорение наследников имеет cap и diminishing returns по поколениям.

Если QR активирует новый владелец с заполненным Курятником, применяется тот же временный «В гостях» flow.

Blockchain/NFT-воплощение **не входит в v1/v2**. Идея сохраняется в backlog как отдельная механика с самостоятельным юридическим и платформенным проектированием.

---

# 34. Player-to-player рынок

Старое решение «игроки продают курочек друг другу за GE» **не входит в Game Bible v1**.

Причины:
- конфликтует с запретом прямых GE-переводов;
- требует отдельной экономики, антифрода и правил settlement;
- усложняет collectible balance до того, как сформирована базовая экономика.

В v1 курочки:
- выдаются системой;
- покупаются у системы, если функция открыта;
- выигрываются;
- наследуются.

P2P market — Future Research.

---

# 35. Ставки на Arena

Идея ставок на исход боёв, победителей сезона или события **не включается в основной Game Bible v1**.

Она сохраняется как отдельный Future-модуль:
**Arena Predictions / Wagers Research.**

До разработки нужно отдельно определить:
- используется ли GE или отдельный бесплатный prediction-point;
- юридическую квалификацию;
- store/platform restrictions;
- антифрод и договорные матчи;
- влияние на несовершеннолетних/возрастные ограничения;
- невозможность вывода выигрыша в деньги.

Core Arena не должна зависеть от ставок.

# 37. Противоречия со старыми документами — новые решения имеют приоритет

Следующие старые решения считать **superseded**:

1. «Курочка только до L4 на первом этапе, затем прежняя специализация с L5» → новая модель L1–20 и семь основательниц.
2. «Специализацию выбирает пользователь» → в v1 у конкретной курочки свой характер/Дар; classes — future taxonomy.
3. «GE только игровая единица» → GE является общим бонусным ресурсом QuRa и может иметь финансовое discount-применение по отдельным правилам.
4. «Рефералка 10/5/2» → актуально 20/10/4.
5. «Наследница сразу того же уровня» → наследник начинает L1, но получает Legacy и ускорение.
6. «P2P биржа курочек как обязательная часть» → Future.
7. «30 уровней яйценоскости» → текущий progression cap L20.
8. «Arena только будущая абстракция» → заложены stats/gear/1×1→2×2→3×3.
9. «Энергия как ресурс» → выключена; используются игровые билеты.
10. «365 событий» → 60–80 базовых событий с вариантами и реакциями.
11. «Вывод как обязательное игровое задание» → задания создаются только по реально включённым финансовым feature flags.

# 38. Критические нюансы, которые нельзя потерять при реализации

## 38.1. GE — экономически чувствительный ресурс
Если GE можно применить к реальным товарам/скидкам, любой игровой GE-faucet имеет реальную стоимость. Mini-game RNG, daily production, referrals, chests и Arena rewards должны проходить budget simulation.

## 38.2. Главная курочка ≠ единственная активная
XP получает главная, но Дары всех жителей могут работать на Курятник по правилам stacking.

## 38.3. Battle Power ≠ Coolness
Не использовать Крутость для matchmaking.

## 38.4. Temporary modifiers ≠ permanent stats
Morale, buff и Daily Event не должны навсегда менять item/chicken data.

## 38.5. Overflow — обязательный UX
Нельзя уничтожать редкую курочку/предмет мгновенно из-за заполненного Курятника/Сундука.

## 38.6. Store visibility
Недоступные по уровню предметы видны затемнёнными: пользователь должен знать, к чему стремиться. Купить/надеть их нельзя.

## 38.7. Feature gates
Не давать задания на функцию, которой нет в production.

# 41. Источник правды

До появления последующих документов:
- этот Game Bible является источником правды по игровой концепции;
- конкретные цифры, явно названные «гипотезой», не являются production balance;
- Economy/DB/Arena Specs смогут уточнять числа, но не должны менять принципы без нового decision record.

**Главный критерий любой новой механики:** она должна либо повышать удержание, помогать пользователю освоить QuRa, создавать осмысленный GE sink/collection goal или давать социальную/соревновательную ценность. Если механика не делает ничего из этого — она не нужна.
