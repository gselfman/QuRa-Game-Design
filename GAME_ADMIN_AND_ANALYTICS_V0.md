# QuRa Game Admin & Analytics v0.1 — интерфейс оператора и измерение интереса

**Статус:** функциональная спецификация для разработки, рекомендуемые пороги PROTOTYPE BALANCE. Не смешивать с admin финансового процессинга. Реальные цены GE/фиатные настройки только с отдельным правом доступа и подтверждением.

## 2. Конфигурация — не «бортянка» без структуры

Единый searchable реестр `GameConfigDefinition`: `key`, `module`, `description_ru`, `type`, `unit`, `min/max`, `default`, `current`, `proposed`, `status`, `version`, `scope`, `effective_at`, `updated_by`, `audit_reason`, `dependencies`, `risk`. Верхняя панель: поиск, фильтры, массовое изменение, diff, импорт/экспорт, safe preview. Форматы: integer, decimal, percent, enum, formula, JSON-schema.

Оператор видит для каждого изменения: **старое → новое**, прогноз XP/день, скорость L3/L4/L10/L15, среднюю стоимость сборки, GE issuance/liability, сундуки EV, насколько вырос/снизился шанс победы персонажа и на сколько пользователей повлияет. Каждый прогноз выводить как диапазон и отмечать симуляционные допущения.

Workflow: черновик → валидация зависимостей → симуляция → второе согласование для финансово-значимых параметров → canary → публикация → аудит → rollback. Жёсткие ограничения: нельзя создать гарантированный положительный GE цикл, отрицательную цену, предмет с неработающим статом, unchecked XP source, непубликуемые odds или сломанный порядок уровней.

RBAC: viewer, content-editor, balance-designer, economy-approver, admin, compliance. Audit log append-only. Любые реальные корректировки GE только через централизованный ledger и отдельные финансовые разрешения. Пользовательская приватность, агрегаты и k-anonymity для маленьких групп.

## 3. Интерактивный симулятор

Input: набор параметров версии, количество игроков, сегменты поведения (новые/регулярные, пользующиеся финтехом/только игра, регион/язык), горизонт 1/7/30/90 дней. 1 000–100 000 виртуальных игроков/прогонов с seeded RNG и диапазонами неопределённости. Output: time-to-level p10/p50/p90, частота уровней, XP sources, GE issuance и sink, BP/power spread, fairness по архетипу, средняя стоимость 1 пользователя/день, число paid bot attempts, вероятность пустой очереди, EV наград, share inactive items. Для боёв отдельный pairwise matrix шести героинь по уровням/экипировке, target window 45–55% в симметричных условиях (PROTOTYPE BALANCE).

## 5. Дашборд — главные вопросы руководителя

| Виджет | Формула / сегментация | Какое решение помогает принять |
|---|---|---|
| Игровые DAU/WAU/MAU | уникальные игроки с осмысленным `game_open` | Игра вообще используется? |
| D1/D7/D30 game retention | вернулись в день N после первого входа; когорты по дате первого входа | Хочется ли возвращаться? |
| Activation | % открывших игру → выбравших героиню → L4 → первый бой | На каком шаге теряем новичков? |
| Time to first joy | медиана до первого L up/выбора героини | Не затянут ли старт? |
| Игровые сессии | sessions/user/day; p50/p90 active minutes; доля 2+ сессий | Возвращаются ли в течение дня? |
| Gameplay depth | % используют задания, корм, ежедневные события, Arena, магазин | Какие механики действительно востребованы? |
| Бои | всего, human/bot, free/paid, победы, пропуски, p50 matchmaking time | Работает ли Arena? |
| Прогрессия | level distribution, p50 дней до L4/10/15, dropoff на уровнях | Слишком быстро/медленно? |
| Курочки | выбор шести, retention по выбранному архетипу, active roster | Есть ли бесполезный Дар? |
| Магазин | browse→buy, buyers, orders, GE sink, SKU conversion, refund | Какую цену менять? |
| Предметы | received→equipped→used in battle, инвентарь неиспользуемых | Какие предметы бессмысленны? |
| Корм и GE-яйца | число кормлений, взрослые несушки, начисленные GE/сутки/курочку, коэффициенты, лимиты, заявки на сбор, отложенные начисления | Сколько стоит обещание пассивной яйценоскости и достаточно ли оно мотивирует игрока? |
| GE финансы | отдельно passive_laying GE, GE за платежи, игры и рефералов; spent in game, redeemed by partner, actual cost of redemption, outstanding liability, net faucet | Устойчив ли бонус и окупается ли привлечение/удержание? |
| QuRa core uplift | доля игроков с квалифицированными финоперациями vs сопоставимая контрольная группа | Не отвлекает ли игра от кошелька? |
| Когорты / эксперименты | контроль/тест, конверсия и удержание, доверительные интервалы | Помогло ли изменение? |
| Сообщения | opt-in, доставлено, открыто, отключено, жалобы | Не раздражают ли уведомления? |

Не делать вид, будто корреляция «сыграл→заплатил» доказывает причинность; для влияния на финансовую активность нужен рандомизированный holdout и заранее определённая метрика.

## 6. Первый эксперимент и сигналы тревоги

Рекомендуемые мягкие цели закрытого запуска (не обещания и не индустриальные нормы QuRa): onboarding completion >=65%, D1 >=30%, D7 >=10%, >=35% игроков совершили два осмысленных игровых действия в первые сутки, возврат к игре 2+ раза/день у 20% активных; контроль ошибок вознаграждений <0.1% (целевой 0). Учитывать малые выборки, интервалы и разделять платёжных/non-paying пользователей. Эти пороги требуют подтверждения; не оптимизировать только «время в игре» в ущерб QuRa.


## 7. Симулятор роста золотых яиц и накопления

Применять матрицу из `GE_LAYING_PROGRESSION_AND_SHOP_V02.md`. Оператор настраивает ставки GE по L3–L20, бонусы Дара/корма, цену обычного инкубационного яйца, цены SKU и расширений Курятника, видит p25/p50/p75 дни до цели и прогноз погашения GE партнёрами. Обязательно показывать, что минимум 1 GE на цыплёнка L3+/сутки LOCKED; поправки выше минимума — PROTOTYPE BALANCE. Сегменты: только пассивный игрок, активный плательщик, игрок мини-игр, смешанный сценарий, коллекционер с 24 курочками. Проекция строится по фактическому earned GE и учитывает пропуски дней и промежуточные покупки, а не предполагает бесконечный рост всех курочек сразу.
