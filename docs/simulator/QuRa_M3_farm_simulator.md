# QuRa — M3: симулятор Курятника и экономики GE

**Статус:** исходный код и тесты опубликованы в GitHub; автоматическая проверка выполнения пока НЕ ПОДТВЕРЖДЕНА. Node.js 20+, ES-модули без внешних зависимостей. Это исследовательская модель, не production QuRa.

## Файлы
- `tools/farm-simulator-m3.mjs`: модель Курятника, несколько курочек, XP, уровни, пассивные GE, обычные инкубационные яйца, покупки, расширения и сценарии.
- `tests/farm-simulator-m3.test.mjs`: 9 тестов инвариантов.
- `tools/farm-demo-m3.mjs`: сравнение трёх когорт на 30 дней и сценарий 90 дней.
- Переиспользуются `tools/behavior-simulator.mjs` (XP и seeded RNG) и `tools/ge-economy-simulator.mjs` (ставки GE и цены).

## Запуск
```sh
node --test tests/farm-simulator-m3.test.mjs
node tools/farm-demo-m3.mjs
```

## Что моделируется
- L1–L2 — обычное яйцо, L3 — цыплёнок, L4+ — взрослая курочка.
- С L3 пассивно не меньше 1 GE/сутки независимо от входа, по рабочей таблице L3–L20.
- Каждая курочка имеет собственный XP, уровень и id.
- Вместимость Курятника 2/4/6/10/16/24; первое расширение 2→4 бесплатно, далее цены из текущей модели.
- Покупка за GE обычного инкубационного яйца создаёт L1, а не взрослую курочку.
- Вторая курочка — milestone первой на L6; третья в прототипе — развитие второй до L4. **Реальный путь «Хозяйство» ещё не проверяется**, поэтому milestone третьей нельзя считать полностью реализованным.
- Базовая экипировка по рабочей цене, GE списываются один раз с баланса модели.
- 30-дневные когортные профили explorer / wallet / gamer с фиксированным генератором псевдослучайных чисел.

## Технический контракт
`createFarm`, `hatchEgg`, `awardXP`, `buyItem`, `upgradeCoop`, `purchaseEgg`, `grantMilestoneEgg`, `claimMilestoneEgg`, `simulateFarm`, `compareFarmScenarios`.

Модель каждый день: возможные действия по вероятностям → XP и уровни → milestones → начисление GE каждой L3+ курочке → выбор расходов → сохранение снимка состояния. Пассивные GE считаются офлайн.

## Ограничения и будущая работа
- Это модель исследовательского поведения, **не подключение к действующим пользователям/кошелькам**. Доходы финансовых операций задаются параметрами.
- Нет дневного XP cap по всем источникам; нет расходов на дополнительные платные бои за 3 GE; бесплатные бои смоделированы как один вероятностный пакет до 4 на день.
- Покупка третьего яйца через milestone ещё не включает проверку главы «Хозяйство»; временное правило — для эксперимента.
- Нет продажи GE-пакетов, динамического выбора целей, произвольного квестового календаря, скидок Гламурочки и полной синергии Даров.
- В расчёте дневных ставок используются числовые дробные GE; production-правила округления/аккумуляции не реализованы.
- Для M4 нужны Монте-Карло по множеству пользователей, конфигурируемые распределения, таблицы p25/p50/p75, сравнение конфигураций и контроль устойчивости.
- Отдельно потребуются real-world validation, антифрод, idempotency GE ledger и проверки affordability/возвратов.

## DoD следующего шага
1. В CI исполняются тесты M2 и M3.
2. При фиксированных seed результаты одинаковы и экспортируются в JSON/CSV.
3. Каждая курочка L3+ сохраняет минимум 1 GE/сутки; недопустимы отрицательные балансы и превышение capacity.
4. Покупки и выдача milestones не дублируются.
5. Неопределённые игровые параметры управляются версией конфигурации и не выдаются за продакшен-тариф.
