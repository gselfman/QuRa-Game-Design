## Основное решение для MVP
Одна утверждённая CARD-база на героиню/версию. Внешность сохраняется, сменная одежда отделяется. Нельзя накладывать новую шляпу поверх старой. Нужны чистое тело и отдельные штатные предметы, восстанавливающие исходный вид, когда выбран default loadout. Это требует отдельной подготовки растра; она пока не выполнена.

Сначала вертикальный срез одной Рябы: HEAD+EYES+BODY+CARRY+FEET. После визуальной проверки переносить правила на остальные героини и позы. Никаких автоматических обещаний универсальной посадки на шесть разных силуэтов.

## Система координат
Мастер-холст 1024×1024 RGBA (предлагаемый контракт экспорта, не заявление о разрешении исходника). Origin в левом верхнем углу. u=x/W, v=y/H. Один root для всех частей. Не обрезать прозрачные поля самостоятельно. При trim экспортировать offsetX/offsetY относительно мастер-холста. UI карточка и масштаб тела — разные системы: рамка не задаёт якоря анатомии.

Для каждой пары characterId+pose+baseVersion свой anchor profile. Для предмета свой pivot, опорная ширина/высота, передние/задние части и маски. Одной точки недостаточно: очки требуют двух глазных ориентиров; шляпа — линии посадки на голове; жилет — плеч/груди/талии; обувь — отдельного контура и ориентира каждой лапы.

## Перекрытия
Фиксированного универсального z-order недостаточно: каждая поза получает occlusion map. Задняя часть шляпы позади головы, передняя поверх неё, гребень — по вырезу/маске. Жилет за передними крыльями; ремень сумки может проходить за крылом, сама сумка — перед ним. Рюкзак за телом, передние лямки перед ним. Для обуви тело ноги и пальцы нельзя оставлять поверх закрытого сапога. Глаза и клюв остаются открытыми; эмоции заменяют только выделенную лицевую область, без повторного тела и одежды.

Предлагаемые слои: gear_back → base_body → body/waist/front_straps → front_wings → carried_item → face/neck → eyes_gear → head_front → FX. При необходимости base_body разбивается на head/body/wings/feet; плоский текущий PNG такой структуры не имеет.

## Экспорт
ICON отдельно от wearable overlay. Имена: qura_<item>_<character>_<pose>_<part>_v01.png. part=back/front/mask либо конкретная часть; profile JSON хранит версии баз, pivot, occlusion, occupiedSlots и supportedPoses. Не масштабировать иконку и не объявлять её overlay. Полноразмерные PNG каждой части сохраняют один холст и origin. Автоматическое увеличение растра не добавляет исходных деталей.

## Проверка одного комплекта
1. Утвердить CARD master и неизменяемые черты Рябы.
2. Подготовить clean base и штатные аксессуары; исходный вид восстановим из слоёв.
3. Один тестовый комплект: G01_01 шляпа, G01_05 очки, G01_11 жилет, G01_14 сумка, G01_17 обувь. Это перечень проверки, не утверждение что текущие концепты готовы.
4. Проверить каждый предмет отдельно и комплектом на 512px, 256px, 128px высоты CARD: отсутствие двойной одежды, утечки старых предметов, клиппинга и висящих ремней; лицо читается.
5. Для 4 эмоций проверить неизменные глаза/голову/плечи/лапы по якорям. Предлагаемый допуск стыка 2px на холсте 1024 (0.2%), отдельно подтвердить на финальном масштабе.
6. CARD целиком проходит runtime перемещение/наклон вместе с экипировкой, без независимого дрейфа частей.
7. Затем PERCH/NEST с собственными anchor/occlusion profiles; если в NEST лапы спрятаны, FEET скрыт целиком по profile, без плавающей обуви. Поддержка поз объявляется только после проверки.

## Открытый выбор
За основу разметки взят 18:75 как кандидат, потому что пользователь направил к этим референсам. Это не утверждает его как финальную CARD. Нужен выбор владельца: сохранить этот полный стоящий силуэт для Арены или указать иной утверждённый CARD. После выбора финально измеряем ориентиры и только затем готовим overlays.
